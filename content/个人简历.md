### 禅道 MCP · 全栈开发

**2025.11 - 2025.12**

#### 项目概述

go-zentao-mcp 是一款由我个人开源维护的禅道 MCP（Model Context Protocol）服务器，使用 Go 实现，将禅道项目管理系统的主要 API 以 MCP 工具的形式暴露，供支持 MCP 的 AI 助手或 IDE 等客户端调用，从而在对话或工作流中完成查询需求、任务、Bug、创建用户、管理产品与项目等操作。服务器通过 stdio 与 MCP 客户端通信，启动时从环境变量读取禅道地址（`ZENTAO_BASE_URL`）及可选账号密码（`ZENTAO_ACCOUNT`、`ZENTAO_PASSWORD`），支持自动登录获取 Token；用户也可通过 `zentao_login`、`zentao_set_token` 等工具手动完成认证。当前共注册 82 个 MCP 工具，覆盖认证、用户、项目集、产品、项目、需求、版本、执行、任务、Bug、测试用例、测试单、反馈、工单等禅道能力，与禅道官方 REST API 一一对应。技术栈为 Go 1.21+，依赖 `github.com/mark3labs/mcp-go` 实现 MCP 协议与服务器框架，禅道 HTTP 调用封装在 zentao 包内；提供构建、启动、测试、调试脚本及部署文档，支持 SSH 隧道、Docker、HTTP/WebSocket 等外网部署方式。

#### 人员分工

该项目为个人主导的开源项目，由我独立完成架构设计、禅道 API 与 MCP 工具的一一映射、请求与响应的类型定义与错误处理，以及配套的测试、脚本与部署文档。社区通过 Issue 或 Pull Request 反馈兼容性与需求，由我进行维护与版本发布。

#### 本人职责

在 zentao 包中封装禅道 REST API 客户端（含 Token 认证、通用 HTTP 请求与各接口的请求/响应类型定义），在 main 中基于 mcp-go 创建 MCP 服务器并注册全部 82 个工具，每个工具对应一个禅道 API 调用，包含规范的 name、description、inputSchema 与 handler。实现启动时根据环境变量自动登录、未配置时提示使用 zentao_login 手动登录的逻辑，并编写 README、TEST.md、SCRIPTS.md、DEPLOYMENT.md 等文档；提供 Windows 与 Linux/macOS 的构建与启动脚本，以及集成测试与单元测试。

1. 在公司内部将该开源项目推广落地，经推广后基本覆盖全体开发人员使用，使团队在 Cursor、Claude Desktop 等 IDE 与 AI 中可直接查询与操作禅道需求、任务、Bug 等，减少在浏览器与禅道之间来回切换，提升日常开发与协作效率。

### Tpush / Tpush-Client · 全栈开发

**2025.08 - 2025.09**

#### 项目概述

Tpush 是一套面向 Twitter（X）运营自动化的前后端分离 + 桌面客户端解决方案，由 Tpush（Web 管理端）与 Tpush-Client（Electron 桌面客户端）组成。管理端负责任务配置、素材管理、定时任务与设备监控；客户端安装在运营人员本地，执行下发的自动化任务，并连接浏览器管理服务完成账号登录、发推等操作。两项目通过统一的后端 API 与 SSE 实时通道协作，形成「Web 配置 → 服务端 → 客户端执行 → 浏览器自动化」的完整链路。

技术栈：管理端采用 Vue3、Vite、TypeScript、Element Plus、Pinia、Tailwind，基于 pure-admin-thin；客户端在此基础上增加 Electron、Puppeteer-core、SSE、electron-store、electron-updater，基于 electron-pure-admin，并实现延迟队列对 Browser API 的限流与顺序执行。

#### 人员分工

#### 本人职责

- **Tpush 管理端：** 从路由规划、接口封装到页面组件的设计与实现，包括账号管理、推特素材（列表与采集详情）、任务列表（含报表与批量操作）、定时任务、机器列表（客户端管理）等；统一 TypeScript 与 Pinia；参与构建与部署配置。  
- **Tpush-Client：** 设计并实现 Browser API 的延迟队列（DelayQueue）机制；SSE 与任务事件与前端状态联动；preload、ipc 与主进程通信；Electron 主进程与 XOperator（Puppeteer）集成联调，浏览器实例复用与自动更新等。

#### 业绩

1. DelayQueue 对 Browser API 统一限流与顺序执行（默认 5 秒间隔），降低并发压力，并输出《延迟队列使用说明》。  
2. SSE 长连接与前端状态打通，任务更新等事件实时下发与本地状态刷新。  
3. 管理端落地「账号 → 素材 → 任务 → 定时 → 设备」管理闭环。  
4. Electron + Puppeteer 自动化链路联调，Windows 打包与 electron-updater 自动更新。  
5. 统一 TypeScript、Pinia、Vite 及代码规范（Commitlint、ESLint、Prettier 等）。

### gost-server · 全栈开发

**2025.02 - 2025.03**

#### 项目概述

gost-serve 是一套围绕 gost 代理集群构建的后端服务，负责账号管理、流量计费、黑名单控制以及代理服务的统一配置和治理。项目基于 Go，通过 HTTP 和 gRPC 双协议对外提供接口，以 Redis 作为账号、流量和路由数据的存储，向上为运维平台或控制面板提供能力，向下对接 gost 进程，实现服务发现、端口分配和转发策略管理。整体架构包括配置中心、Redis 仓储层、业务代理层（与 gost 交互）以及 HTTP/gRPC 接入层，支持以命令行方式启动不同服务进程。

#### 人员分工

后端团队负责业务设计与核心代码开发；运维侧负责部署、监控以及与现有代理集群、日志系统的集成；我主要负责 gost-serve 的整体后端实现与命令行启动工具的设计，同时参与配置文件规范的制定和调试工具编写。

#### 本人职责

基于 go-cmd 设计 http、grpc、config、test 等子命令；基于 go-web 搭建 HTTP 接口与统一中间件。基于 Redis 设计账号、流量、黑名单等 key 结构，实现仓储逻辑并封装 repository 层；结合 gost 配置模型，提供代理 Service 创建、删除与按需生成，端口自动分配与配置持久化。参与 gRPC 协议定义与实现；HTTP 路由拆分 Redis 管理、gost 管理、新账号创建等路由组。编写配置读写模块与常见错误场景提示。

#### 业绩

1. HTTP/gRPC 统一对外暴露账号、流量和代理配置能力，替代零散脚本，降低运维成本。  
2. 基于 Redis 的账号和流量计费模型，支撑后续计费与风控策略。
